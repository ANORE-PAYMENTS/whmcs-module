# Anore для WHMCS

Модуль создаёт платёж через актуальный Anore API, открывает пейформу и зачисляет оплату инвойсу WHMCS после подписанного события `payment.succeeded`.

## Требования

- PHP 8.1+ с cURL и JSON, совместимый с установленной версией WHMCS. Для WHMCS 9.0 нужен PHP 8.2 или 8.3 — см. [требования WHMCS](https://docs.whmcs.com/9-0/installation-guide/system-requirements/).
- MySQL/MariaDB с `GET_LOCK` и правом создания таблицы истории платежей.
- Инвойсы в RUB или USD. `Convert To For Processing` отключён: валюта обработки должна совпадать с валютой инвойса.
- Публичный HTTPS-доступ к callback без CAPTCHA, браузерной авторизации и перенаправлений.

## Установка и обновление

Скопируйте **оба** файла из каталога `modules` в корень WHMCS, сохранив пути:

```text
modules/gateways/anore.php
modules/gateways/callback/anore.php
```

При обновлении сначала сделайте копию старых файлов. Сохранённые настройки шлюза и таблицу `mod_anore_payments` удалять не нужно: callback продолжает читать старые записи. Новая таблица `mod_anore_payment_attempts` создаётся автоматически при первом открытии оплаты и хранит все попытки отдельно. Сборка Java-бэкенда для обновления этого модуля не нужна.

Откройте `System Settings → Payment Gateways → All Payment Gateways`, активируйте `Anore` и заполните:

| Настройка | Значение |
| --- | --- |
| API URL | `https://api.anore.cc`; также принимается адрес с `/api/v1` или `/v1` |
| API-ключ | Bearer-ключ из кабинета Anore |
| Секрет API-ключа | Для подписи запроса `X-ZPay-Signature`, если задан для ключа |
| Shop ID | Для ключа уровня аккаунта; для ключа магазина оставьте пустым |
| Секрет вебхука | Точное значение секрета вебхука этого магазина в Anore, обязательно |
| Методы оплаты | Необязательно: `sbp,card,yoomoney,crypto,crypto-old`; пусто — методы магазина |
| Источник `user_identity` | `ID клиента из инвойса` (рекомендуется), `Email` или `Telegram ID из custom field` |
| Custom field ID для Telegram ID | Числовой ID клиентского поля; обязателен только для Telegram-режима |
| Custom field ID для Telegram username | Необязательный числовой ID клиентского поля |
| Режим франшизы магазина | Явно `Выключен` или `Включён`; обязан совпадать с режимом магазина ANORE |
| Тип/адрес/владелец франшизы | Обязательны при включённом режиме; см. строгие правила ниже |

> **Важно:** `user_identity` пока принимается API как необязательный, но скоро станет обязательным. Эта версия модуля всегда формирует и отправляет его. Не откладывайте настройку корректного источника идентичности.

Для `external_id` модуль читает владельца непосредственно из `tblinvoices.userid` под блокировкой инвойса и не доверяет переданному клиентом ID. Email берётся только из `clientdetails.email`, очищается и приводится к нижнему регистру. Telegram ID и username читаются только по явно заданным **числовым ID** клиентских custom fields из `tblcustomfieldsvalues`; изменяемые имена полей никогда не используются. ID должен быть положительным каноническим signed-64 decimal, username — 5–32 символа `A–Z`, `0–9`, `_` (ведущий `@` нормализуется).

При включённом режиме франшизы модуль требует `type`, `address` и `owner_telegram_id` до сетевого запроса. Для `telegram_bot` адрес — канонический username. Для `website` принимается только HTTPS origin без credentials, нестандартного порта, path, query и fragment. При выключенном режиме объект `franchise` не отправляется: API требует его для магазинов с franchise mode и запрещает для остальных.

Старые названия `dvnet` и `xrocket` автоматически преобразуются в `crypto` и `crypto-old`.

Модуль передаёт email клиента и `callbackUrl` при создании платежа. Callback строится из `System URL` WHMCS; проверьте, что там указан публичный HTTPS-адрес установки. Этот же адрес можно сохранить в настройках магазина Anore:

```text
https://ВАШ-WHMCS/modules/gateways/callback/anore.php
```

## Создание платежа

Используется `POST /api/v1/payments`: сумма, валюта, описание, ID инвойса в `orderId`, email клиента, канонический `user_identity`, условный `franchise`, callback и адрес возврата. Модуль не отправляет эти данные в Payso и вообще не вызывает Payso. Подпись запроса считается по исходному JSON.

Перед созданием или повторным использованием ссылки модуль проверяет актуальные статус и остаток инвойса через [GetInvoice](https://developers.whmcs.com/api-reference/getinvoice/). Для закрытого счёта или изменившейся суммы новая ссылка не создаётся. Действующая ссылка используется повторно, только если совпадают сумма, валюта и настройки платежа. Срок действия учитывается в UTC.

Каждая новая ссылка получает отдельную запись истории. Поэтому запоздавшая оплата по предыдущей ссылке продолжает сопоставляться с исходным инвойсом. Если разные ссылки одного инвойса действительно оплачены, каждый отдельный платёж передаётся в стандартный `addInvoicePayment`; остаток и переплату обрабатывает WHMCS.

## Обработка вебхуков

Callback загружает служебные файлы из корня WHMCS по [официальной схеме](https://github.com/WHMCS/sample-gateway-module/blob/master/modules/gateways/callback/gatewaymodule.php). Он проверяет HMAC-SHA256 в `Anore-Signature`, UUID платежа, сумму, валюту и связь с инвойсом. Если `orderId` отсутствует, ID инвойса берётся только из сохранённой записи платежа. В USD используется исходная `amount`, а не рублёвая `rubAmount`.

Зачисление и создание новых ссылок одного инвойса защищены общей блокировкой. Повтор одного UUID не зачисляется второй раз. Ошибка журналирования или обновления вспомогательного статуса после сохранения транзакции не превращает успешную оплату в ошибку callback. `payment.expired` меняет только ещё не оплаченные попытки и не откатывает оплаченный инвойс.

| HTTP | Значение |
| --- | --- |
| `200` | Оплата записана, повтор уже записанной оплаты, истечение ссылки или событие, не требующее действий |
| `400` | Пустой/повреждённый JSON или некорректные обязательные поля |
| `401` | Неверная подпись |
| `405` | Запрос не методом POST |
| `422` | Несовпадение суммы/валюты/инвойса, неизвестный платёж или инвойс, требующий ручной сверки |
| `503` | Временный сбой БД, занятая блокировка, ошибка зачисления или недоступная конфигурация; доставку нужно повторить |

Валидные события и их повторы не должны получать ложные `400/500`. Ошибочные и неподписанные запросы по-прежнему отклоняются; подтверждать незачисленную оплату ответом `200` нельзя.

### Старые неуспешные доставки

После обновления повторите доставку неуспешных событий. Уже записанный в `tblaccounts` UUID подтвердится без повторного зачисления, даже если запись старого кэша утрачена.

Старая версия могла перезаписать единственную связь инвойса с предыдущей платёжной ссылкой. Если такой платёж ещё не зачислен и его запись уже утрачена, callback вернёт `422` с `Payment mapping not found; manual reconciliation required`. Для него нужна ручная сверка Anore и WHMCS; обновление не восстанавливает утраченную историю автоматически.

## Автоматические проверки

Из корня этого репозитория:

```bash
php -l modules/gateways/anore.php
php -l modules/gateways/callback/anore.php
node tests/callback-http.mjs /путь/к/php
```

Если модуль открыт внутри репозитория zpay, перед путями добавьте `integrations/whmcs/`.

Тесты запускают настоящий PHP HTTP-сервер и локальную имитацию Anore API; проверяют создание платежей, identity/franchise и их строгую валидацию, подписи, повторные и запоздавшие доставки, ошибки зачисления и логирования. Учёт WHMCS и БД заменены тестовой реализацией. Лицензированный WHMCS и конкурентная работа настоящей MySQL этим набором не проверяются; перед установкой на рабочий биллинг проверьте модуль на тестовой установке своей версии WHMCS.

CI выполняет этот набор на PHP 8.1–8.4. `scripts/build-release.sh` детерминированно собирает `dist/anore-whmcs-module.tar.gz` и `dist/SHA256SUMS` из отслеживаемых файлов модуля; workflow сохраняет их только как CI artifact и ничего не публикует, не тегирует и не развёртывает.
